1Introduction & scope

This document describes the PlentyMarkets REST API endpoints that the plenty_client Ruby gem calls, together with the authentication scheme, headers, pagination, throttling and error conventions it relies on.

plenty_client is a thin Ruby wrapper around the PlentyMarkets REST API. It performs no business validation of its own — it is a transport-layer gateway that maps Ruby method calls onto HTTP requests against a PlentyMarkets instance. Every endpoint listed in section 8 corresponds to a public method on a PlentyClient::* class or module.

The catalogue covers 503 endpoints over 297 distinct paths and 125 client classes, spanning 21 top-level resource areas. It is intended for integration partners — including PlentyMarkets — who need to understand precisely which parts of the REST API this integration touches.

Authoritative source. Paths, HTTP verbs and parameters in this document were extracted directly from the gem source code for version 0.1.3. Where the meaning of a field or response body is required, the official PlentyMarkets REST API documentation remains authoritative.

3Authentication & token lifecycle

The client authenticates with username/password credentials and then uses a Bearer access token for all subsequent calls. Authentication is performed lazily: before any request, if no valid token is held, the client issues a login.

Authentication endpoints

MethodEndpoint pathClient call
POST/rest/loginAuthentication.login
POST/rest/login/refreshAuthentication.login_refresh
GET/rest/oauth/access_tokenAuthentication.access_token
POST/rest/client-loginAuthentication.client_access_token
POST/rest/logoutAuthentication.logout

Token flow

  1. The client sends POST /rest/login with { "username", "password" }.
  2. The response supplies accessToken, refreshToken and expiresIn (seconds). The token expiry is stored as now + expiresIn.
  3. Every request thereafter sends Authorization: Bearer <accessToken>.
  4. A token is treated as valid only while it is more than 60 seconds from expiry; inside that window the client re-authenticates before issuing the request.
Credentials required. site_url, api_user and api_password must be configured; a request attempted without them raises before any network call.

4Request & response conventions

Request headers

Content-Typeapplication/json
Acceptapplication/x.plentymarkets.v1+json
AuthorizationBearer <accessToken> (once authenticated)

Bodies & query parameters

GET and DELETE requests pass parameters as the query string; POST, PUT and PATCH send a JSON-encoded body. One group of bulk endpoints (/rest/pim/variations/*, §8.21) accepts a JSON array body on DELETE.

Responses

Responses are parsed as JSON. application/pdf responses (document downloads) are returned as a raw binary body. An empty response body is returned as null.

5Pagination

List endpoints are paginated. The client sends a page query parameter (1-based) and reads the paged envelope returned by the API, which includes entries and the boolean isLastPage. Common optional parameters include itemsPerPage and with.

The Ruby API exposes two modes: a single-page call returns the raw response, while passing a block iterates every page automatically — repeatedly requesting incrementing page values and yielding each page's entries until isLastPage is true.

6Rate limiting, retries & timeouts

PlentyMarkets enforces request throttling and returns the remaining short-period allowance in response headers. The client reads these and proactively paces itself:

X-Plenty-Global-Short-Period-Calls-LeftRemaining calls in the current short window.
X-Plenty-Global-Short-Period-DecaySeconds until the window resets.

When the remaining short-period allowance drops to one or fewer, the client defers the next request until the decay window has elapsed. In addition, transient throttling and availability responses are retried automatically:

Retried statuses429 (rate limited) and 503 (unavailable).
Retried methodsGET, POST, PUT, PATCH, DELETE.
BackoffExponential with jitter — base 0.5 s, factor ×2, capped at 30 s.
Max attempts3 (configurable).
TimeoutsConnection open 5 s, total 30 s (both configurable).

7Error handling

HTTP status codes are mapped onto a small exception hierarchy, and JSON error payloads are inspected for validation and credential failures.

3xxRaises a redirection error.
4xxRaises a client error. A body containing “no query results” is surfaced as a not-found error.
5xxRaises a server error.
Credential failureAn invalid_credentials error payload raises a specific invalid-credentials error.
Validation failurevalidation_errors in the payload are collected and raised as a response error.

9Client configuration reference

The client is configured through PlentyClient::Config. The settings relevant to integration behaviour:

site_url
Base URL of the PlentyMarkets instance. The host is reused and paths are mounted under /rest.
api_user / api_password
Credentials used for POST /rest/login.
plenty_id
PlentyMarkets client (tenant) identifier.
attempt_count
Maximum HTTP attempts for retryable responses (default 3).
open_timeout / timeout
Connection-open and total request timeouts in seconds (defaults 5 / 30).
log
When enabled, requests are logged with the password field filtered out.
